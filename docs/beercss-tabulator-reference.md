# Beer CSS / Tabulator 実装リファレンスメモ

## 目的
members系・task-detail系のUI実装で、ライブラリの推奨パターンから外れてUXを崩さないための参照メモです。

## Beer CSS（参照: https://www.beercss.com/）
- ダイアログは `dialog` + `nav` + `footer` の構成を基本にする。
- フォームは `field border label` を基準にし、入力群は `grid` で段組みする。
- 一覧の行は `row middle-align` を使い、情報と操作ボタンを左右分離する。
- 状態表示は `chip` を使って短く示す。長文をチップに詰め込まない。
- 全面ローディングより、対象セクション内の `progress` を優先する。

## Tabulator（参照: https://tabulator.info/docs/6.3）
- 列定義は `columns` に集約し、表示変換は formatterで最小限に行う。
- データ更新は全再生成より、必要なタイミングだけ `setData` / 再描画を行う。
- ソート・フィルタ・選択状態はホスト側状態で保持し、テーブル再初期化時に復元する。
- 重い処理を減らすため、表示前にホスト側で整形してからテーブルへ渡す。
- クリック応答性を優先し、操作開始時にUI反応を返してから非同期更新を行う。

## ZARMS向け適用ルール
1. モーダルは即時オープン、データ再取得は表示後にバックグラウンドで行う。
2. 失敗時はモーダルを閉じず、対象エリアだけエラーメッセージを表示する。
3. 保存後の全体再同期は非同期で実行し、操作の体感待ち時間を増やさない。
4. Board / task-detail で使っている余白・列配置・操作導線を優先して踏襲する。
