# モバイルアプリ 稼働管理（出欠）セットアップ手順

## 目的・前提
本ドキュメントは、mobile-appの稼働管理（attendance）タブを正しく動作させるために必要な設定や設定項目をまとめたものです。
稼働管理では、実行委員の稼働開始・終了予定時間の登録および、当日の位置情報を利用した稼働実績の手動打刻（開始・終了）を管理します。

## スプレッドシート `members` シートの必須カラム
稼働管理の予定・実績は `members` テーブル（スプレッドシート上の `members` シート）に保存されます。以下のカラムが用意されている必要があります。

| カラム名 | 意味 | 入力・記録形式 |
| --- | --- | --- |
| `fri_planned_start_at` | 金曜_稼働開始_予定 | `HH:mm`形式 |
| `fri_planned_end_at` | 金曜_稼働終了_予定 | `HH:mm`形式 |
| `fri_actual_start_at` | 金曜_稼働開始_実績 | `HH:mm`形式 |
| `fri_actual_end_at` | 金曜_稼働終了_実績 | `HH:mm`形式 |
| `sat_planned_start_at` | 土曜_稼働開始_予定 | `HH:mm`形式 |
| `sat_planned_end_at` | 土曜_稼働終了_予定 | `HH:mm`形式 |
| `sat_actual_start_at` | 土曜_稼働開始_実績 | `HH:mm`形式 |
| `sat_actual_end_at` | 土曜_稼働終了_実績 | `HH:mm`形式 |
| `sun_planned_start_at` | 日曜_稼働開始_予定 | `HH:mm`形式 |
| `sun_planned_end_at` | 日曜_稼働終了_予定 | `HH:mm`形式 |
| `sun_actual_start_at` | 日曜_稼働開始_実績 | `HH:mm`形式 |
| `sun_actual_end_at` | 日曜_稼働終了_実績 | `HH:mm`形式 |

＊ `docs/database-schema.mmd` との対応も上記のとおりとなります。

## 定数設定 (`constants.js`)
`projects/mobile-app/src/constants.js` にて、以下の設定が存在し正しい値が入力されている必要があります。

1. **`FESTIVAL_DATE`**
   - 基準となる開催日（金曜日）を `YYYY-MM-DD` 形式で指定します。
   - `fri` が `+0`日, `sat` が `+1`日, `sun` が `+2`日の基準となります。
2. **`ATTENDANCE_GEOFENCE`**
   - オブジェクトとして、会場の緯度・経度と半径を指定します。
   - 形式例: `{ LATITUDE: 35.64, LONGITUDE: 140.03, RADIUS_METERS: 200 }`

## 稼働管理の仕様説明

- **同一 input 運用**
  開始・終了予定の入力用 `input` は、打刻実績が入ると兼用で実績表示のフィールドに切り替わります。
- **blur 自動保存**
  予定入力フィールドは、フォーカスが外れた（blur）タイミングで自動的に変更差分があるか判定し、予定時刻を保存します。
- **打刻時の表示と disabled**
  稼働開始・終了として実績の打刻が行われたフィールドは、その時点の実績時間が反映され自動的に `disabled` 状態になります。
- **セッション中取消**
  開始打刻をした直後など、セッション中（画面リロード等を行う前）であれば「取消」ボタンが表示されます。これを使用して直近の誤打刻を取消し、予定状態に戻すことが可能です。
- **再打刻ブロック**
  サーバーサイドでも再打刻を防止するバリデーションが行われます。既に実績時刻が入っているフィールドに対して、無効な更新リクエストを送信してもエラーとして弾かれます（明示的な取消操作以外）。

## 本番切替時の確認項目
運用前に以下が正しく設定されているか確認してください。

- **権限**: 操作を行うユーザーが `members` テーブル自身のレコードに対して適切な更新権限を持っているか。
- **位置情報許可**: ブラウザの設定や端末の設定で、Webアプリに位置情報取得が許可されている状態か。
- **ジオフェンス**: `ATTENDANCE_GEOFENCE` が実際の会場を正しくカバーした緯度・経度・半径で設定されているか。
- **保存失敗時の確認**: `blur` 時の保存エラーが発生した場合等、スナックバーやアラートを通したエラー通知が表示されるか確認する。

## トラブルシュート

- **位置情報が取得できない / 拒否される**
  ユーザーの端末またはブラウザで位置情報サービスが有効になっていること、ならびにドメインに対する許可が行われているか確認してください。
- **会場範囲外と表示される**
  ジオフェンスの中心位置および半径と、GPSの測定精度に問題がないか確認してください。一時的に許容半径（`RADIUS_METERS`）を広げることで解決する場合があります。
- **エラー: テーブルに列が存在しない等**
  スプレッドシートの `members` シートに、上記必須カラム十二種が漏れなく存在しているか確認してください。
- **権限不足エラー**
  Google Apps Scriptの実行権限、またZARMSシステム内でのアクセス権限が与えられているか確認してください。
- **再打刻が拒否される**
  意図せず複数回打刻が行われた場合など、既に記録済みの実績を上書きしようとするとサーバーにて拒否される仕様です。誤打刻の際は、セッション中に表示される「取消」ボタンを使用してください。
