# 自律実装サイクルガイド

## 目的
長時間連続作業でもコンテキストを肥大化させず、一定品質で実装を継続するための運転手順です。

## 90分サイクル
1. Discovery（20分）
- Exploreサブエージェントを2〜3本起動し、対象領域の不足機能と影響範囲を抽出する。
- 出力は「修正ファイル」「関数」「受け入れ条件」の3点に限定する。

2. Implement（40分）
- 1サイクルで扱う対象を最大3ファイルに絞る。
- 変更は最小差分で行い、既存APIとUIパターンを優先再利用する。

3. Verify（20分）
- get_errorsで構文・参照エラーを確認する。
- frontendは最低1回 dev デプロイし、反映可否を確認する。

4. Log（10分）
- docs/table-coverage-checklist.md を更新する。
- docs/testing-guide.md に検証ケース追記が必要なら反映する。
- 未解決課題を次サイクルの先頭タスクへ繰り越す。

## サブエージェント利用ルール
- タスクごとに必ずExploreサブエージェントを起動する。
- 調査結果はそのサイクルで使う最小情報だけ採用し、全文を持ち越さない。
- 仕様競合がある場合はプロジェクト規約を優先する。

## 実行コマンド
```bash
npm run deploy:frontend:dev
npm run deploy:db:dev
npm run deploy:all:dev
```

## 完了判定
- 対象テーブルの閲覧/編集/保存/再読込が全て通る。
- 失敗時に再同期され、画面状態とDB状態の不一致が残らない。
- チェックシート更新とテスト観点がドキュメントに反映済み。
