# UI/パフォーマンス設計ガイド

## モーダル表示の基本方針
- モーダルはクリック直後に必ず開く。
- モーダル表示のためにDB再取得を待たない。
- 追加データが必要な場合は「開いた後」にローディングを表示し、非同期で更新する。

## 実装ルール
1. 初期描画は `App.state.data` を使う。
2. 最新化が必要な場合はバックグラウンド更新を行う。
3. 再同期失敗時でもモーダルを閉じない。
4. 保存処理後の全体再読込は同期で待たず、背景で実行する。

## Beer CSS利用ルール
- レイアウトは `row`, `grid`, `field`, `chip`, `button` の既存クラスを優先する。
- 一覧項目は `row middle-align` で縦崩れを防ぐ。
- カード内で情報を詰め込みすぎず、操作ボタン群を右側に分離する。

## Tabulator利用ルール
- 初期表示を最優先し、重い整形はホスト側で済ませてから渡す。
- iframe通信はトークン検証付き `postMessage` を維持する。
- クリック操作で再描画が必要な場合でも、全面ローディングではなく対象エリアのみ更新する。
